# 2 分钟项目演示脚本

## 录制前准备

- 启动 MySQL 和 Spring Boot，确认控制台没有报错。
- 打开 Postman Collection，并按顺序排列 5 个请求。
- 清理无关窗口、通知和敏感信息，不展示数据库密码或 API Key。
- 将录屏分辨率设置为 1080p，浏览器和 Postman 字号保证手机端也能看清。

## 时间安排

### 0 至 15 秒 项目介绍

讲述：

> 这是一个基于 Spring Boot、MyBatis-Plus 和 MySQL 的 AI 工单助手，面向校园设备报修场景，包含登录、建单、查询、状态流转和 AI 分类 5 个接口。

画面：快速展示 README 顶部、技术栈和接口表。

### 15 至 35 秒 登录

运行 `01 登录`，指出响应中的 Token 已被 Postman 自动保存。

讲述：

> 用户登录后获得 Token，后续请求通过 Authorization 请求头完成身份校验。当前版本使用内存 Token，服务重启后失效。

### 35 至 60 秒 创建和查询工单

依次运行 `02 创建工单`、`03 查询工单`。

讲述：

> 创建工单时，系统在同一事务中写入工单和操作日志，保证两条数据同时成功或同时回滚。创建后可以按时间倒序查询，也可以按状态筛选。

### 60 至 90 秒 状态机和并发控制

运行 `04 修改状态`，展示 `PENDING` 变为 `PROCESSING`；再使用非法状态演示业务拒绝。

讲述：

> 状态变更先校验允许的流转，再使用工单 ID 和旧状态作为更新条件，避免并发请求相互覆盖；每次变更都会写入日志。

### 90 至 110 秒 AI 分类和降级

运行 `05 AI 分类`，展示 `category` 和 `summary`。

讲述：

> AI 接口要求模型返回固定 JSON，并校验分类枚举。模型超时、格式错误或没有配置 Key 时，会重试并使用关键词规则降级，保证工单主流程可用。

### 110 至 120 秒 总结

讲述：

> 当前版本已经完成核心后端闭环。下一步会增加 BCrypt、JWT、角色权限、分页查询和核心业务自动化测试。

画面：回到 README 的后续计划，不展示个人账号或密钥。
